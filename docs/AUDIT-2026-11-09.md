# Audit de FingerprinterJS — 9 novembre 2026

> Audit historique du commit v2 indiqué ci-dessous. La refonte v3 est décrite dans le [suivi des corrections](REMEDIATION.md). Les reproductions et chiffres de ce document décrivent la base auditée, pas la version corrigée.

Le projet possède une base exploitable : 19 collecteurs séparés, une configuration TypeScript stricte, aucune dépendance d’exécution, une licence MIT et un paquet npm dont les trois bundles correspondent au code actuel. En revanche, les garanties d’identification stable, les scores de confiance et la promesse « enterprise-grade » dépassent ce que l’implémentation et les tests démontrent.

La priorité est de rendre les contrats fiables : définition du hash, délais, erreurs, exports, tests et publication. Ajouter des collecteurs ou de l’apprentissage automatique avant ce travail augmenterait la surface de maintenance sans résoudre les problèmes actuels.

Le positionnement recommandé est une bibliothèque ouverte de signaux de navigateur et d’empreintes explicables, utilisable localement et sans service imposé. Une empreinte est un indice de rapprochement entre environnements ; elle ne prouve ni l’identité d’une personne, ni l’authenticité d’un appareil, ni l’absence de fraude.

### Essais dans de vrais moteurs de navigateur

Essais automatisés sur macOS ARM, page locale, contexte neuf par moteur, trois générations puis un rechargement. Il s’agit des navigateurs fournis par Playwright, pas d’une certification de toutes les versions de Chrome, Firefox ou Safari.

| Moteur | Version | Première génération | Deux suivantes | Hash stable sur les essais et le rechargement | Sans audio ni WebRTC, un essai |
| --- | --- | --- | --- | --- | --- |
| Chromium | 158.0.8127.18 | 1 446 ms | 131 / 125 ms | Oui | 4 ms |
| Firefox | 159.0 | 405 ms | 117 / 119 ms | Oui | 47 ms |
| WebKit | 27.2 | 474 ms | 115 / 110 ms | Oui | 8 ms |

Aucune erreur JavaScript de page n’a été observée. Ces quelques mesures montrent le coût des collectes optionnelles ; elles ne constituent pas un benchmark statistique. Elles ne démontrent pas une stabilité sur plusieurs semaines, après mise à jour du navigateur, changement de matériel ou modification des permissions.

Les trois moteurs donnent `confidence: 100` et `entropy: 141`. Firefox et WebKit donnent pourtant `supported: false` pour la batterie et la connexion : le calcul actuel ne distingue donc pas correctement collecte disponible et réponse de remplacement.

## Constats prioritaires

**P1** : à traiter avant de recommander le projet pour des décisions sensibles ou une intégration de production. **P2** : nécessaire pour faciliter une adoption et une maintenance professionnelles. **P3** : amélioration secondaire. La priorité exprime l’impact sur le projet ; ce n’est pas un score CVSS.

### F01 — P1 — Les options de délai et de parallélisme n’ont pas d’effet

**Code :** [options](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/types.ts#L109), [collecte principale](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/fingerprint.ts#L241), [collecte sans hash](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/fingerprint.ts#L341), [permissions](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/collectors/permissions.ts#L48), [quota](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/collectors/storage.ts#L76).

`timeout` et `parallel` sont acceptés et stockés, mais jamais utilisés par l’orchestrateur. `parallel: false` lance quand même les collecteurs ensemble. Le délai fourni ne configure pas les classes asynchrones ; certaines opérations, notamment les permissions et le quota de stockage, n’utilisent aucun délai.

**Reproduction :** deux collecteurs retardés de 60 ms démarrent immédiatement malgré `parallel: false`. Un collecteur dont la promesse ne se termine jamais reste en attente après 50 ms avec `timeout: 1`.

**Correction :** un seul moteur de collecte pour `generate()` et `getComponents()`, un délai par collecteur, un budget total et un résultat partiel explicite. Prévoir `AbortSignal`, annuler ce qui peut l’être et fermer les ressources. Une promesse gagnant une course de délais n’annule pas l’opération perdante ; un délai JavaScript ne peut pas non plus interrompre une boucle synchrone bloquante.

### F02 — P1 — Le test de stockage peut supprimer une donnée de l’application

**Code :** [stockage local et de session](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/collectors/storage.ts#L35).

Les deux sondes écrivent `__fp_test__`, puis suppriment cette clé sans préserver une éventuelle valeur existante. Ce comportement est confirmé dans les trois moteurs : les valeurs de test représentant des données de l’application disparaissent.

**Correction :** utiliser une clé propre à chaque invocation, ne jamais écraser une clé existante et nettoyer dans un `finally`. Tester aussi l’échec d’écriture et les appels concurrents. Une bibliothèque intégrable doit limiter et documenter ses effets sur le stockage de l’hôte.

### F03 — P1 — La stabilité est décidée au niveau du collecteur entier

**Code :** [inclusion dans le hash](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/fingerprint.ts#L270), [écran](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/collectors/basic.ts#L95), [Client Hints](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/collectors/clienthints.ts#L67), [stockage](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/collectors/storage.ts#L25), [périphériques](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/collectors/media.ts#L33).

Un simple `metadata.stable` inclut tout le résultat dans le hash. Sont ainsi inclus la résolution disponible, le ratio de pixels, les versions complètes du navigateur, le quota de stockage et le nombre de périphériques multimédias.

Ces valeurs peuvent évoluer pendant la vie d’un même environnement. Les listes de périphériques dépendent notamment des autorisations ; le quota dépend de l’origine et de sa politique ; les Client Hints contiennent des marques et un ordre volontairement variables selon les implémentations et versions. [Documentation des périphériques](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/enumerateDevices), [documentation du quota](https://developer.mozilla.org/en-US/docs/Web/API/StorageManager/estimate), [spécification des Client Hints](https://wicg.github.io/ua-client-hints/#create-brands).

**Correction :** définir une projection de champs explicitement destinés au hash pour chaque collecteur. Séparer observation brute et représentation d’identification. Définir la durée et les conditions de stabilité visées, puis les mesurer. Les essais courts sont concluants ; la garantie générale du README ne l’est pas.

### F04 — P1 — La sérialisation ne produit pas une représentation canonique

**Code :** [sérialisation](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/utils.ts#L49), [source du hash](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/fingerprint.ts#L304).

Deux `customData` sémantiquement identiques, `{ a: 1, b: 2 }` et `{ b: 2, a: 1 }`, produisent des empreintes différentes. `safeStringify()` remplace aussi une référence partagée par `[Circular]` même sans cycle : `{ a: objet, b: objet }` diffère de deux copies égales du même objet. Les valeurs `BigInt` restent susceptibles de faire échouer `JSON.stringify()` alors que `customData` accepte `unknown`.

**Correction :** contrat de données sérialisables précis, tri récursif des clés d’objet, traitement explicite des valeurs non JSON et des cycles. Préserver l’ordre des tableaux lorsque cet ordre a un sens ; normaliser individuellement ceux qui représentent un ensemble. Versionner cette représentation, car sa correction modifiera les empreintes existantes.

### F05 — P1 — La normalisation supprime des identifiants métier légitimes

**Code :** [normalisation](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/fingerprint.ts#L141).

Tout UUID est supprimé, quelle que soit sa clé : deux `userId` UUID différents deviennent identiques après normalisation. Les clés `salt`, `sessionId`, `date` et d’autres sont retirées sans contrat propre à l’intégration. Inversement, le filtrage est superficiel : `customData.meta.timestamp` reste dans le hash et le fait varier.

**Correction :** garder le contexte métier hors du hash par défaut, ou demander explicitement quels champs doivent y entrer. Éviter de deviner la stabilité à partir de la forme d’un UUID ou d’un grand nombre. Pour une migration compatible, conserver l’ancien comportement sous une version de schéma clairement identifiée.

### F06 — P1 — La fonction appelée SHA-256 peut retourner un hash faible

**Code :** [fonction de hash](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/utils.ts#L24), [hash de remplacement](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/utils.ts#L8).

En absence de `crypto.subtle`, `sha256()` utilise silencieusement un hash entier de 32 bits, puis une valeur absolue. La sortie n’a plus les propriétés ni la longueur d’un SHA-256. Reproduction : `Aa` et `BB` donnent tous deux `840` dans cette branche. Elle devient notamment pertinente hors des contextes sécurisés requis par Web Crypto. [Documentation de Web Crypto](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto).

**Correction :** implémentation SHA-256 de secours vérifiée, ou erreur explicite avec information d’algorithme. Ne pas dégrader silencieusement un contrat cryptographique. Tester des vecteurs connus et distinguer résistance aux collisions du hash et unicité des données collectées : un SHA-256 ne rend pas un navigateur unique.

### F07 — P1 — Les scores de confiance et d’entropie sont trompeurs

**Code :** [détection d’erreur](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/fingerprint.ts#L217), [confiance](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/fingerprint.ts#L275), [entropie](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/fingerprint.ts#L201).

`confidence` est essentiellement la proportion de collecteurs sans une erreur reconnue, pas une probabilité de reconnaître le bon appareil. `supported: false`, un objet vide ou `no-canvas-context` peuvent compter comme succès. Exclure tous les collecteurs produit `NaN` ; n’en garder qu’un peut produire 100 %.

`entropy` additionne des constantes, y compris pour des collecteurs non disponibles ou exclus du hash. Les corrélations entre UA, plateforme, Client Hints et matériel ne sont pas prises en compte. Les **141 bits** observés sont donc une somme configurée, pas une mesure de population.

**Correction :** exposer d’abord une couverture de collecte et des états `ok`, `unsupported`, `blocked`, `timeout`, `error`, `excluded`. Distinguer absence d’information et valeur réellement observée. Réserver tout indicateur de précision ou d’entropie statistique à une méthode mesurée et documentée ; ne pas corriger seulement le nombre affiché.

### F08 — P1 — L’analyseur pénalise des situations normales

**Code :** [addition du score](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/suspect-analyzer.ts#L50), [langue et fuseau](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/suspect-analyzer.ts#L426), [API manquantes](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/suspect-analyzer.ts#L520), [règle « trop parfait »](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/suspect-analyzer.ts#L581).

Un ensemble de composants sans erreur déclenche `too_perfect` : **30 points, niveau MEDIUM**. L’analyse d’un objet vide ou d’un jeu de données où deux collecteurs de base ont été volontairement exclus donne **90 points, niveau HIGH**, via `missing_apis` et `too_perfect`.

D’autres règles assimilent à de la suspicion certaines combinaisons de langue et de pays, des définitions d’écran courantes, le rendu logiciel ou la protection contre le fingerprinting. `hasCanvasNoise()` ne compare pas deux rendus : il vérifie leur longueur. `navigator.webdriver` déclenche également plusieurs signaux corrélés. Aucun taux de faux positifs ou de faux négatifs n’est établi.

**Correction :** retirer `too_perfect`, traiter les exclusions comme non évaluables, distinguer automatisation, manque d’information et protection de la vie privée. Versionner les règles et rendre chaque conclusion explicable. Valider sur des cas légitimes variés avant de recommander un seuil. Les exemples d’antifraude doivent présenter les signaux comme un complément à une décision côté serveur ; un client peut falsifier son résultat ou ne jamais exécuter le SDK.

### F09 — P1 — Les tests ne protègent pas la propriété principale du produit

**Code :** [mocks de stabilité](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/__tests__/stability.test.ts#L9), [mocks de génération](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/__tests__/fingerprint.test.ts#L11), [tests de hash](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/__tests__/utils.test.ts#L25).

Le faux encodeur retourne toujours les mêmes octets et le faux décodeur toujours `decoded`. Le calcul simulé de hash ne dépend donc pas des données comme le suggère son commentaire. Les tests vérifient surtout l’égalité et la forme des résultats, sans établir qu’une entrée pertinente différente change l’empreinte.

**Preuve :** dans une copie temporaire du projet, le remplacement complet de `sha256()` par `return "constant-hash-for-all-inputs"` laisse les **25 tests réussir**. Le code du dépôt n’a pas été modifié pour cette expérience.

**Correction :** tests de propriétés avec un vrai encodeur et un vrai SHA-256 : mêmes données normalisées → même hash ; champ d’identification différent → hash différent ; donnée hors identification → même hash. Ajouter les délais, erreurs, exclusions, interruptions et tests de consommateurs du paquet. Compléter avec des essais Chromium/Firefox/WebKit. Augmenter la couverture doit servir ces contrats, sans se limiter à atteindre un pourcentage.

### F10 — P1 — Une entrée publique du paquet est cassée

**Code :** [exports du paquet](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/package.json#L8), [configuration Rollup](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/rollup.config.js#L3).

`fingerprinter-js/collectors` pointe vers `dist/collectors/index.js`, qui n’est produit ni par le build ni présent dans l’archive npm publiée. Un import ESM échoue avec `ERR_MODULE_NOT_FOUND` ; un `require` n’a pas de condition d’export correspondante.

Le paquet déclare aussi `types` après `import` et `require`. La documentation Node recommande de placer cette condition en premier. Le test TypeScript avec `moduleResolution: nodenext` échoue sur `new Fingerprint()` après import par défaut ; l’import nommé et le mode `bundler` du cas testé fonctionnent. [Conditions d’exports Node](https://nodejs.org/api/packages.html#community-conditions-definitions).

**Correction :** construire réellement les points d’entrée annoncés ; définir des formats ESM/CJS et déclarations cohérents, sans ambiguïté d’extensions. Installer le `.tgz` dans des projets consommateurs et tester import nommé, import par défaut, CJS, ESM, `bundler` et `nodenext`. Importer la bibliothèque sur un serveur peut être utile au build d’une application ; la collecte elle-même reste une opération de navigateur.

### F11 — P1 — La chaîne de publication contient plusieurs défauts indépendants

**Code :** [workflow](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/.github/workflows/publish.yml#L60), [script local](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/scripts/publish.sh#L41).

Le workflow publie `package-npm.json` comme s’il s’agissait d’un paquet : ce fichier n’est ni le répertoire d’un paquet ni son archive. La suppression de `publishConfig` par `sed` laisse aussi un JSON invalide avec la structure actuelle. Le job GitHub Packages garde le nom non scopé et le `publishConfig.registry` npm du paquet. Le déclenchement manuel change la version sans enregistrer cette version dans le dépôt.

Le script local modifie le manifeste et la configuration du registre, sans restauration garantie en cas d’échec. Il crée commit et tag avant la publication, utilise une variante de `sed` propre à macOS et déclenche un push de `main` et des tags. Ces comportements rendent les reprises d’échec difficiles.

Le [workflow du 31 janvier 2026, heure de Paris](https://github.com/Lorenzo-Coslado/fingerprinter-js/actions/runs/21534370220) confirme les deux jobs de publication en échec. Leurs logs ne sont plus disponibles via l’API, qui renvoie 410 : la cause historique exacte n’est donc pas attribuée à un défaut particulier.

**Correction :** commencer par une seule destination npm ; version et tag cohérents, construction d’une archive, validation puis publication de cette même archive. Utiliser OIDC et la provenance lorsque configurés. npm documente un minimum de Node 22.14 et npm 11.5.1 pour le trusted publishing ; la CI actuelle utilise Node 18. [Publication npm](https://docs.npmjs.com/cli/v11/commands/npm-publish/), [trusted publishing](https://docs.npmjs.com/trusted-publishers/).

### F12 — P1 — Les contrôles de qualité ne s’exécutent pas sur les contributions

**Code :** [ESLint](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/.eslintrc.js#L3), [workflows](https://github.com/Lorenzo-Coslado/fingerprinter-js/tree/a9ba5f02ce6fad4139a32130fa367b0781493b6a/.github/workflows/), [configuration Jest](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/jest.config.js#L1).

`extends: "@typescript-eslint/recommended"` est invalide pour cette configuration ; l’entrée attendue est de la forme `plugin:@typescript-eslint/recommended`. Le lint ne s’exécute donc pas. Les tests et le build sont lancés par le workflow de publication, pas par un workflow de validation de chaque pull request. CodeQL s’exécute sur les PR, mais ne remplace pas les tests fonctionnels.

**Correction :** CI de contribution avec installation verrouillée, lint, vérification des types, tests, build et essais du paquet. Ajouter les tests de navigateurs sur les chemins critiques. Définir un format et un style uniques, appliqués automatiquement. Les règles de protection de branche et les permissions des comptes npm n’ont pas été vérifiées dans cet audit.

### F13 — P2 — Les ressources et le coût de collecte sont mal maîtrisés

**Code :** [course de délais](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/collectors/base.ts#L82), [WebRTC](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/collectors/webrtc.ts#L55), [audio](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/collectors/advanced.ts#L47), [polices](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/collectors/advanced.ts#L172), [WebGL](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/collectors/canvas.ts#L102).

Les temporisateurs de `withTimeout()` ne sont pas annulés après succès. La connexion WebRTC est fermée sur le chemin réussi, pas dans un `finally`. Un dépassement de délai ne ferme pas la ressource sous-jacente. Les contextes WebGL ne sont pas explicitement libérés. Le collecteur de polices alterne écritures de styles et lectures de dimensions, ce qui peut provoquer des calculs synchrones de mise en page. L’audio utilise un contexte temps réel et `createScriptProcessor()`.

Tous les collecteurs sont activés même sans analyse de suspicion, alors que cinq sont exclus du hash. Sur les essais effectués, retirer audio et WebRTC réduit fortement le temps de collecte.

**Correction :** cycle de vie explicite, nettoyage dans `finally`, temporisateurs annulés, collecte coûteuse déclenchée seulement lorsqu’elle est utile. Mesurer le temps par collecteur et les longues tâches sur mobile avant d’optimiser. `Promise.all()` ne déplace pas les calculs synchrones hors du thread principal.

### F14 — P1 — La collecte par défaut a un effet réseau peu visible

**Code :** [activation par défaut](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/fingerprint.ts#L101), [serveur STUN imposé](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/collectors/webrtc.ts#L55), [données retournées](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/fingerprint.ts#L317).

WebRTC ouvre une connexion avec `stun:stun.l.google.com:19302` dès la génération par défaut. Cette dépendance réseau est importante pour une intégration professionnelle, même si le SDK n’envoie pas l’ensemble de ses composants à un service de collecte. La propriété `localIPs` peut contenir des adresses de candidats publics ; le nom ne décrit pas strictement ce qu’elle contient.

Le SDK retourne par ailleurs toutes les observations brutes, y compris celles exclues du hash. Le README ne décrit pas suffisamment le trafic, les lectures et écritures, les finalités et les modalités de minimisation.

**Correction :** fonctionnement sans accès réseau par défaut ; WebRTC explicitement activable et serveur configurable si nécessaire. Documenter les effets de chaque collecteur et proposer une sortie réduite. Prévoir une intégration avec le déclenchement autorisé par l’application, sans prétendre qu’un booléen de consentement rend une intégration conforme.

En France, la CNIL inclut le fingerprinting dans les traceurs. La nécessité du consentement dépend notamment de la finalité et des exemptions applicables ; une finalité d’authentification ou de sécurité ne dispense pas automatiquement tous les autres usages. Le projet doit aider l’intégrateur à distinguer sécurité, mesure d’audience et suivi. [Règles et exemples d’exemptions de la CNIL](https://cnil.fr/fr/cookies-et-autres-traceurs/que-dit-la-loi). La minimisation et la dégradation correcte pour les utilisateurs protégeant leur vie privée sont aussi cohérentes avec les [recommandations du groupe de travail du W3C](https://www.w3.org/TR/fingerprinting-guidance/).

### F15 — P2 — L’API typée ne décrit pas précisément les états réels

**Code :** [types de résultats](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/types.ts#L15), [interfaces de composants](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/types.ts#L153), [exports publics](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/index.ts#L10), [orchestrateur](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/fingerprint.ts#L228).

`components: Record<string, unknown>` impose des assertions aux consommateurs malgré l’existence des interfaces métier. Plusieurs collecteurs renvoient un objet contenant seulement `error` sous un type qui exige de nombreux champs, via `as`. `CollectorResult` et les poids de confiance déclarés ne structurent pas le résultat effectivement retourné.

La liste des collecteurs, leur initialisation, les options d’exclusion et les exports sont maintenus séparément. `generate()` et `getComponents()` dupliquent la logique de collecte et de normalisation. Les extensions publiques existent comme classes et interfaces, mais il manque un point d’injection documenté dans l’orchestrateur.

**Correction :** registre typé unique des collecteurs et de leurs projections, moteur de collecte partagé, résultats discriminés par statut et carte de composants typée. Conserver une interface simple pour le cas courant ; permettre des collecteurs personnalisés sans obliger à manipuler des champs privés. Éviter une infrastructure de plugins complexe pour seulement 19 collecteurs.

### F16 — P2 — Versions, documentation et maintenance se contredisent

**Code :** [version embarquée](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/src/types.ts#L299), [version npm](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/package.json#L3), [sécurité](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/SECURITY.md#L9), [changelog](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/CHANGELOG.md#L8), [contribution](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/CONTRIBUTING.md#L221), [exemple](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/examples/usage-examples.ts#L12).

Le paquet est en 2.0.1, mais `VERSION` et les résultats annoncent 2.0.0. Le changelog s’arrête à 1.0.0 ; la politique de sécurité annonce seulement le support de 1.x. CONTRIBUTING contient un contact fictif et une réponse sous 48 h, quand SECURITY parle de 72 h. Les consignes de style ne correspondent pas entièrement au code.

`npm run demo` vise un dossier `demo` absent ; un exemple HTML charge `dist/fingerprinter.umd.js`, alors que le build produit `dist/index.umd.js`. L’exemple de fraude place montant et transaction dans `customData`, ce qui peut rendre l’empreinte propre à une transaction. Les versions minimales de navigateur annoncées ne sont pas validées par la suite de tests.

L’outillage mélange Jest 29 et son environnement jsdom 30 ; ESLint 8 est déprécié. Les dépendances verrouillées présentent les alertes décrites plus haut. Node 14 dans les prérequis et Node 18 dans la CI ne constituent plus une base de maintenance actuelle. [État officiel des versions Node](https://nodejs.org/en/about/previous-releases), [versions en fin de vie](https://nodejs.org/en/about/eol).

**Correction :** version embarquée générée depuis une seule source, guide de migration, changelog actuel, versions réellement soutenues et procédure de sécurité praticable. Aligner l’outillage sur des versions maintenues, sans appliquer aveuglément `npm audit fix --force`. Le lockfile est suivi par Git mais figure dans `.gitignore` : retirer cette contradiction. L’historique local contient un seul contributeur humain ; documenter une reprise de maintenance et des attentes réalistes facilite l’adoption par des équipes.

### F17 — P3 — La démonstration interpole des observations dans du HTML

**Code :** [rendu des composants](https://github.com/Lorenzo-Coslado/fingerprinter-js/blob/a9ba5f02ce6fad4139a32130fa367b0781493b6a/docs/index.html#L819).

`JSON.stringify(data)` est inséré directement dans `innerHTML`, à l’intérieur d’un `pre`. Cela n’échappe pas les caractères HTML. C’est un point d’injection à durcir si des collecteurs personnalisés ou des données externes sont ajoutés. Aucun scénario d’exploitation distante de la démonstration actuelle n’a été établi.

**Correction :** créer les éléments et affecter les observations via `textContent`. Garder la démo comme exemple d’intégration copiable, avec collecte déclenchée explicitement et explication des états indisponibles.

## Fonctionnalités à développer

Les fonctionnalités les plus utiles rendent la bibliothèque prévisible, observable et facile à intégrer. Le nombre de collecteurs n’est pas un bon indicateur de maturité.

| Fonctionnalité | Bénéfice pour un développeur individuel | Bénéfice pour une équipe | Priorité |
| --- | --- | --- | --- |
| Profils `minimal`, `balanced`, `diagnostic` | Démarrage rapide sans 19 options | Politique explicite de collecte, coût et effets documentés | Très forte |
| Résultats par collecteur avec état, durée et motif | Comprendre un résultat incomplet | Diagnostic en production sans diffuser les valeurs brutes | Très forte |
| Version du schéma de hash et de la politique de projection | Identifier une rupture lors d’une mise à jour | Migration contrôlée des empreintes stockées | Très forte |
| Budget total, délai par collecteur et annulation | Éviter une interface qui attend indéfiniment | Respecter un budget de performance et arrêter un travail devenu inutile | Très forte |
| Sortie réduite et mode sans réseau | Intégration simple et effets prévisibles | Minimisation, contraintes réseau, revue de sécurité | Très forte |
| Comparaison expliquée de deux observations | Comprendre pourquoi une empreinte a changé | Support et diagnostic des évolutions de schéma | Forte |
| Collecteurs personnalisés typés | Adapter un cas particulier | Étendre sans fork et contrôler le cycle de vie | Forte |
| Analyseur de règles pur et versionné | Tester ses règles sur des fixtures | Rejouer une décision sur un même instantané de signaux | Forte, après correction des règles |
| Exemples exécutables de navigateur, TypeScript et chargement différé en SSR | Copier une intégration fonctionnelle | Tester l’intégration dans les outils de l’équipe | Forte |
| Cache mémoire avec expiration et invalidation explicites | Éviter des collectes répétées | Contrôler fréquence, concurrence et coût | Moyenne, après stabilisation des contrats |
| Outil de compatibilité et export de diagnostic expurgé | Signaler un bug facilement | Reproduire un incident sans partager toutes les observations | Moyenne |

Un éventuel cache doit dépendre du profil, de la configuration et du schéma ; il doit rester désactivable. Il ne faut pas réutiliser durablement un résultat partiel ou devenu obsolète pour donner l’impression de stabilité.

Une API cible pourrait rester courte. L’exemple suivant est une **proposition**, pas une API disponible :

```ts
const fingerprinter = createFingerprinter({
  profile: "balanced",
  network: "disabled",
  timeoutMs: 500,
});

const result = await fingerprinter.generate({ signal });
// fingerprint, fingerprintVersion, collectionCoverage, collectorResults
```

Le profil `minimal` doit désigner précisément les collecteurs exécutés ; « minimal » ne signifie ni anonyme, ni exempté de consentement. La réduction de sortie ne remplace pas la réduction de la collecte.

Une offre hébergée, des tableaux de bord d’identité ou un modèle de machine learning peuvent constituer un produit distinct à terme. Leur intérêt n’est pas établi pour ce dépôt. Une bibliothèque client ne peut pas attester des données de son propre environnement hostile ; même un serveur signant la réception d’un résultat ne certifie pas la véracité des signaux du navigateur.

## Standardisation proposée

| Contrat | Règle à établir |
| --- | --- |
| Identité | Définir ce que représente l’empreinte, sa portée et ses changements attendus |
| Version | Distinguer version npm, version du schéma d’empreinte et version des règles |
| Collecte | Définir états, budget, annulation, effets de bord et comportement partiel |
| Types | Publier un schéma de résultat et des types vérifiés depuis un vrai consommateur |
| Compatibilité | Matrice de navigateurs effectivement testés, limites mobiles et intégration SSR |
| Distribution | Chaque export pointe vers un fichier livré et testé dans le paquet final |
| Contribution | Une commande de validation locale et les mêmes contrôles à chaque PR |
| Publication | Archive validée, version/tag cohérents, provenance et procédure de reprise |
| Vie privée | Inventaire des données et du trafic, collecte minimale, diagnostics expurgés |
| Support | Versions maintenues, procédure de signalement, responsables et délais réalistes |

Pour une bibliothèque locale, le passage d’un petit projet à une grande organisation dépend surtout de ces contrats. Il ne nécessite pas, à lui seul, une architecture de serveur distribuée.

## Feuille de route proposée

### Lot 1 — Rétablir une version de maintenance vérifiable

Périmètre : F09 à F12, cohérence de version et correction des exemples de F16. Ajouter les tests qui échouent sur les défauts constatés, réparer le lint, valider toutes les entrées du paquet et remettre la publication npm sur une chaîne unique. Ce lot peut viser une version corrective si le format d’empreinte reste identique.

**Critères de sortie :** PR validée automatiquement ; vrai hash testé ; paquet installé et compilé dans les modes annoncés ; chaque export utilisable ; version embarquée exacte ; procédure de publication testée sans publier pendant l’audit.

### Lot 2 — Fiabiliser l’exécution et le diagnostic

Périmètre : F01, F02, F07, F13 et F15. Unifier la collecte, nettoyer les ressources, préserver le stockage de l’hôte, représenter correctement les états et exposer les diagnostics utiles. Introduire l’API de contrôle de collecte avec une stratégie de compatibilité explicite.

**Critères de sortie :** aucune attente infinie sur une promesse de collecteur ; résultats partiels identifiables ; annulation et nettoyage vérifiés ; aucune suppression de clé préexistante ; zéro collecteur traité sans `NaN` ni indication trompeuse de confiance.

### Lot 3 — Définir un schéma d’empreinte et des valeurs par défaut pour la v3

Périmètre : F03 à F08 et F14. Définir la projection par champ, la sérialisation canonique, le traitement des données métier et l’algorithme de hash. Revoir les profils et les règles de suspicion. Les changements de valeurs par défaut, de normalisation et de source de hash doivent être traités comme une migration d’empreinte.

**Critères de sortie :** fixtures de référence du schéma, guide v2 → v3, identifiants de schémas incompatibles distinguables, fonctionnement sans trafic STUN par défaut, règles explicables et états inconnus correctement traités. Si les intégrateurs doivent comparer pendant une transition, rendre les versions d’empreinte explicites et calculables à partir d’une collecte partagée lorsque c’est possible.

### Lot 4 — Établir la preuve d’usage professionnel

Périmètre : documentation, intégrations exécutables, essais mobiles et mesure longitudinale sur un panel informé et autorisé. Mesurer séparément stabilité d’un même environnement, collisions entre environnements, couverture de collecte, temps de collecte et faux positifs des règles. Définir la population, l’horizon et les conditions de mesure avec chaque résultat.

**Critères de sortie :** résultats publiables et reproductibles ; politique de support ; exemples consommant le paquet publié ; budget de bundle et de performance ; assertions commerciales limitées aux propriétés réellement établies.

Les lots 1 et 2 forment le chantier immédiat. Le lot 3 mérite une décision de version majeure. Le lot 4 conditionne l’emploi crédible de termes comme « haute précision » ou « enterprise-grade » ; une suite de tests techniques seule ne peut pas établir ces promesses.

## Reproductions et limites

Les commandes de reproduction ci-dessous s’appliquent à une copie du code v2 au commit audité, pas à la v3 corrigée. Pour la v3, utiliser les tests décrits dans le [suivi des corrections](REMEDIATION.md).

Les [résultats consolidés](audit-2026-11-09/results.json) conservent les chiffres et scénarios de cet audit. Le [script de reproduction](audit-2026-11-09/reproduce.cjs) permet de vérifier les propriétés du moteur avec des collecteurs déterministes et un vrai SHA-256, sans API de navigateur ni accès réseau :

```sh
npm ci --ignore-scripts
npm run build
node docs/audit-2026-11-09/reproduce.cjs
```

Les collecteurs synthétiques sont injectés dans les champs compilés pour isoler le moteur : cette technique de test ne constitue pas une API d’extension publique. Le résultat `emptyCollectors.confidence` apparaît comme `null` en JSON parce que sa valeur JavaScript est `NaN` ; le champ `finiteConfidence: false` le rend explicite.

Les essais de navigateur, de paquet et de mutation ont été exécutés dans des contextes temporaires isolés. Aucun code applicatif n’a été corrigé, aucun paquet publié, aucun tag créé et aucun réglage GitHub ou npm changé. Les dépendances et sorties de build nécessaires aux vérifications ont été générées localement dans les dossiers ignorés par Git.

Restent à établir : comportement sur appareils iOS/Android réels et anciens navigateurs annoncés, stabilité de longue durée, précision sur une population représentative, effets des extensions de protection et des politiques d’entreprise, performances sur appareils peu puissants. Les scores mesurés en navigateur automatisé ne permettent pas d’estimer un taux de détection des robots. Cet audit technique ne constitue pas une qualification juridique de chaque future intégration ni un test d’intrusion complet.
