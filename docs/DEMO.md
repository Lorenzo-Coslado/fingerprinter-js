# Browser playground

The repository page at `docs/index.html` loads the local SDK generated by `npm run build:demo`. It uses static HTML, CSS, and JavaScript, with no remote fonts, UI dependencies, CDN import, account, or backend.

```sh
npm ci
npm run demo
```

The default preview is `http://127.0.0.1:4173`. Collection starts only when the visitor chooses **Generate fingerprint** or **Run browser checks**. Results live in page memory and disappear on reload.

The playground supports profiles, exact collector selection, parallel or sequential collection, per-collector timeout, total budget, cancellation, and optional signal interpretation. A second run compares observations with the preceding run. Expand a collector to inspect its local value. Clipboard copying is explicit; diagnostic exports omit fingerprints, signal values, context, and raw error reasons.

The browser checks exercise the real SDK:

1. The SHA-256 `abc` known vector and a changed input.
2. Canonical nested object ordering and its fingerprint.
3. Preservation of UUID context outside the hash.
4. Changed explicit fingerprint data producing a changed hash.
5. Empty collector selection and finite zero coverage.
6. A deliberately pending collector reaching its configured timeout.
7. Preservation of a pre-existing storage key, with cleanup.
8. Two immediate collections using the current settings.

A check can fail or be skipped depending on browser capabilities, settings, and protection policies. These checks do not measure population uniqueness, long-term stability, or bot-detection accuracy. The repeatability check reports what happens rather than hiding a changed result.

The **How it works** panel has a replayable, reduced-motion-aware diagram. Its replay illustrates the pipeline and does not invoke collection. Light/dark selection stays in memory; no preference or fingerprint is persisted by the page.

The interface uses semantic tabs, keyboard arrow navigation, labelled controls, explicit loading/error/empty/cancelled states, expandable table rows, and text-only rendering of observations. The visual system is recorded in `DESIGN.md` at the repository root.
